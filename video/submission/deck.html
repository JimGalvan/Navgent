The problem

Every bug gets checked by hand. Twice, or more.

A ticket comes in with steps, a screenshot or a recording. Before anyone trusts it, someone signs in, sets up the data and clicks through every step. Then they do it all again after the fix.

CHECK 1

Is it still happening?

Old tickets go stale. Nobody knows if the bug is real until someone walks the steps.

CHECK 2

Did the fix work?

The same steps again, by hand, after the deploy, and again the next time someone touches that code.

What Reprobe does

Give it the bug report and a link. Get a verdict with proof.

1 · READ

Written steps, screenshots and screen recordings become a numbered plan. Every step cites its source.

2 · SANDBOX

A fresh browser starts in a disposable gVisor container that can only reach the app under test.

3 · RUN

The agent follows the plan in order, types like a person, and reads form values as well as page text.

4 · PROVE

Reproduced, not reproduced or inconclusive, with expected vs. observed, the step, a recording and the action log.

You can watch live, take over the browser, answer the agent's questions, or stop the run. Run again repeats the same check with one click and keeps every result in the bug's history.

Containment · Blast Radius Zero

Every run is contained, capped and destroyed.

RequirementHow Reprobe enforces it
Process isolationEach run gets its own Docker container under gVisor (runsc). Only Chromium runs inside. No capabilities, no-new-privileges, read-only root.
Resource limits1.5 vCPU, 1536 MB memory, 256 processes, a 900-second container cap and a 600-second agent limit.
Lifecycle disciplineThe container and its firewall rule are removed after every run, on success, failure, cancel or timeout. A reaper runs every 5 minutes.
NetworkOnly the target host on ports 80/443, plus read-only files from a fixed CDN list. Everything else is blocked and logged.
Secret hygieneNo API keys, env vars or mounts in the sandbox. The agent and the inference key stay on the VM and drive Chromium over the Playwright protocol.

Vultr services

Built entirely on Vultr.

CLOUD COMPUTE

One VM runs it all

vhp-4c-8gb-amd in Seattle, Ubuntu 24.04: the web app, the agent, Docker with gVisor, and Caddy for HTTPS.

FIREWALL

Three open ports

Firewall group "reprobe": only TCP 22, 80 and 443 are reachable from the internet. Sandboxes get per-run iptables rules on top.

SERVERLESS INFERENCE

Every model call

glm-5.3 drives the agent loop. glm-5.3-flash reads screenshots and video frames into the plan. No other model provider is configured.

Why it matters

Known bugs stay checked. Fixes get verified.

  • QA and developers stop re-walking the same steps for every stale ticket and every fix.
  • Each verdict comes with proof a reviewer can open: recording, expected vs. observed, the step.
  • A bug's checks live in its run history. One click reruns them after the next change.
  • The agent never holds secrets and can't reach anything but the app it's testing.
